# Wastewater Surveillance Modeling (sample)

A small, runnable pipeline for wastewater-based public health surveillance: quality control of lab results, normalization, site-level trend categories, and short-range forecasts of reported cases that are validated out of sample. All data are **synthetic** (three invented sites); no real site, lab or health-department data are included.

## What it does

```mermaid
flowchart LR
  A[Lab results per sample<br/>target gc/L, PMMoV, flow, LOD] --> B[QC<br/>non-detects = LOD/2, flagged<br/>trailing Hampel outlier screen]
  B --> C[Normalize<br/>target/PMMoV and gc/day per 100k]
  C --> D[Daily causal signal<br/>last sample carried forward, 7-day trailing mean]
  D --> E[15-day trend category per site]
  D --> F[Ridge forecast of cases 7 days ahead]
  F --> G[Rolling-origin validation<br/>vs persistence, interval coverage]
```

1. **QC** (`wws/normalize.py`): non-detects are substituted with LOD/2 and kept visible as a flag; a trailing Hampel filter on log10 concentration flags spikes using only earlier samples.
2. **Normalization**: fecal-strength (target / PMMoV, which can offset dilution and fecal-strength variation, and lab shifts only when both assays shift equally) and flow/population (gene copies per day per 100,000 people). Both are log10-transformed.
3. **Trends** (`wws/trend.py`): a least-squares slope over the last 15 days of the smoothed signal, converted to percent change and labelled. Thresholds are parameters to agree with the surveillance team, not a fixed standard.
4. **Forecasts** (`wws/model.py`): closed-form ridge regression predicting log10(1 + 7-day mean cases per 100k) 7 days ahead. Features use only samples collected up to the forecast date; lab turnaround time and case-report backfill are not modelled and need to be added for operational data.
5. **Validation** (`wws/validate.py`): rolling-origin evaluation (each forecast is tested only on dates the model never saw) with a gap equal to the horizon, a persistence baseline, a fair case-trend comparison on identical rows, direction accuracy, and 90% interval coverage with intervals calibrated on out-of-sample residuals.

## Results on the synthetic data (seed 7, 6 folds, 378 forecasts)

| Model (same rows, same folds) | MAE | Skill vs persistence | Direction accuracy | 90% interval coverage |
|---|---|---|---|---|
| Combined: wastewater + case trend | 0.0698 | 47.8% | 89.9% | 87.0% |
| Case trend only (level, 7/14-day lags, change) | 0.0737 | 44.9% | 85.4% | 85.7% |
| Wastewater, PMMoV-normalized (+ current case level) | 0.0873 | 34.6% | 83.9% | 86.0% |
| Wastewater, flow/population-normalized (+ current case level) | 0.0883 | 33.9% | 81.5% | 87.3% |

MAE is on log10(1 + 7-day mean reported cases per 100k), 7 days ahead. On this synthetic data the case trend alone is already strong; adding wastewater lowers the error modestly. Whether wastewater adds lead time on real data is something to test, not assume. Interval coverage below 90% means the intervals are still slightly narrow and should be recalibrated before results are shared.

## Run it

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python main.py            # writes outputs/report.json, normalized_samples.csv, forecasts_pmmov.csv
python -m pytest -q       # 10 tests: formulas, outlier screen, trends, no temporal leakage, end to end
```

Tested with Python 3.11, numpy 2.4.2, pandas 2.3.3, pytest 9.0.2.

## Adapting to real data

Replace `wws/simulate.py` with a loader that returns the same two tables: samples (site_id, date, target_gc_per_l, below_lod, pmmov_gc_per_l, flow_mld, population) and cases (site_id, date, cases, population). Site-specific LODs, recovery controls, sewershed population estimates and reporting delays should be agreed with the lab and the epidemiology team before modelling.
